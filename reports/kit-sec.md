## Decisions
- Item 2: a check (no 077 bits), not fchmod after create. Creation still asks for 0700.
- Item 3: one helper, `paths::runtime_subdir_in(runtime, name)` (and `runtime_subdir(name)` from the environment): checks the runtime dir, then `private_dir`. Used by listen, runtime_file, icon copies, cache_dir (and its instance dir) and the tiling runtime dir (else a 0755 `chora-tiling` made by the theme writer would now block the shader file). Not fd-based: every caller uses the path afterwards, so an fd check gains nothing; the Refactor row stays open for that and for the copies rows at 0 (XDG_*_HOME, var_os("HOME")).
- Runtime dir check follows a symlink (stat), checks the target. Icon copies fall back to the temp dir only when the runtime dir is unset or no directory; a set but unsafe one refuses (no copy, theme icon).
- Visible: a runtime dir that group or other can write now stops chora at start (listen error) and stops plugin shaders, caches and icon copies. The refusal is a warn line with path and mode.
- Not done: xp launch.rs:167, construct cube start, voice config.rs:1306 keep their runtime_home or /tmp fallbacks (COSMETIC, safe; not in the list).

## Review r1
Seeded review of claude/kit-sec cb2976c1 against a61e8eaa (11 files, +500 -37); no merge gate run. Verdict: **FIX** (1 MAJOR, 4 MINOR, 2 NIT).

- rw-1, MAJOR, flavors/tiling/waybar/waybar.sh:33 and flavors/tiling/wallpaper.sh:10: `mkdir -p "$pids"` makes `chora-tiling/` 0755 under the usual umask 022; when a script runs first (the waybar unit is only `After=chora-tiling.service`, a start race; wallpaper.sh runs without a unit), `runtime_subdir("chora-tiling")` now refuses it until logout: no border or shadow shader, no theme files, `companion()` finds no pid. Fix: `mkdir -p -m 700` in both scripts (and see rw-2).
- rw-2, MINOR, crates/chora-scene/src/paths.rs:77: dirs that the previous release made 0755 (`write_file` create_dir_all for chora-tiling/chora-mc/chora-construct, chora-draw `clear` for cache instances, tiling `write_changed`) stay for the whole login (or with linger) and are refused after an upgrade; the warn names path and mode but not what to do, and the CHANGELOG does not say. Fix: in `private_dir`, chmod 0700 a dir of the euid that is no symlink and has no 022 bits (keep refusing write bits), or name "remove it or log in again" in the message and the CHANGELOG.
- rw-3, MINOR, crates/chora/src/lib.rs:116: `state.listen()` binds `wayland-N` and its lock in XDG_RUNTIME_DIR before `ipc::listen` checks that dir, so the CHANGELOG line "chora opens no socket" is not true. Fix: call `paths::check_runtime_home` on the runtime dir before `state.listen()`.
- rw-4, MINOR, crates/chora-scene/src/paths.rs:118: the runtime dir check follows a symlink and checks only the last component; a symlink owned by another user, or one below a dir that others can write, can be retargeted between the check and the use (protected_symlinks covers sticky dirs only). The owner-only target closes swaps below it, not of the path itself. Fix: canonicalize once in `runtime_subdir_in`, then check and join below the canonical path (or refuse a symlink not owned by the euid).
- rw-5, MINOR, crates/chora-scene/src/paths.rs:77: 0500 is accepted for the runtime dir and for a private dir, but the next mkdir, bind (ipc.rs:229) or write then fails with a bare "Permission denied (os error 13)" without a path. Fix: map the create and bind errors to name the path (or require the owner bits 0300 for dirs that chora writes). Creation stays 0700 & ~umask, never wider.
- rw-6, NIT, crates/chora/src/main.rs:3: the refusal reaches the terminal as `Error: Custom { kind: Other, error: "..." }` (Debug) and names no remedy. Fix: add "chmod 0700 PATH, or set XDG_RUNTIME_DIR to a dir of yours" to the reason.
- rw-7, NIT, crates/chora-kit/src/icons.rs:85: the temp fallback `chora-icons-<pid>` is predictable; another user can make it first and deny icon copies (no planting: owner, mode and symlink are checked). Unchanged from before. Fix: a random suffix.
