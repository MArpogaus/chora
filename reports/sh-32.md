### Cause

Not a compositor exit and not a lost socket. The act harness reads the client list (`clients.list`) before and after each act, and I14 calls every name that is in the first list and not in the second an undeclared disconnect. The tiling session starts the panel of the flavor (`chora-tiling` -> `theme::start_companions` -> `flavors/tiling/waybar/waybar.sh`), which runs `choractl call tiling get_tags` / `choractl outputs` every 2 s, and each waybar module runs `choractl call tiling get_tags` (tag.sh, interval 5) and the helper door reader `chat-door` (services/voice/chat/src/opener.rs:49, "which a panel runs again and again"). Each call is a client of the core for a few milliseconds. A call that the `before` read saw and the `after` read did not is reported as a disconnect. Which act it hits is random.

Log lines (the I14 breach, 7 of 30 runs on the unchanged harness; in all 7 the core was still running at the end of the session, `core_proc.poll()` was None, and its log has no panic):

- `FAIL: tiling I14: in act 'Escape shuts the key list of the keys key': chat-door disconnected, the act did not declare it`
- `FAIL: tiling I14: in act 'a notice shows': choractl disconnected, the act did not declare it` (twice)
- `FAIL: tiling I14: in act 'a helper starts': choractl disconnected, ...`
- `FAIL: tiling I14: in act 'the helper asks': choractl disconnected, ...` (twice)
- `FAIL: tiling I14: in act 'the chat of the helper opens': choractl disconnected, ...`

The train 103 and 104 hits ('Escape shuts the key list of the keys alias key', tiling I14, choractl) are the same line. No product bug: nothing in chora, chora-tiling or the IPC code changed.

### Fix (eb831349, tests/acts only)

- `Session.clients()` leaves out the one-call tools (`ONE_CALL`: choractl, chat-door, chat-opener). The looks, notify, assistant and voice are still watched; a real disconnect of any of them still fails I14. No retry, no declared disconnect.
- Gate line (step 3): `Session.exits()` names the programs of the session that have ended (the core with its code or signal and the last lines of its log, which tests/headless-session.sh keeps in the env file; any other program by its binary). The snapshot carries it and an undeclared disconnect now reads `X disconnected, the act did not declare it (core exited with code 101; last lines: ...)` or `(no program of the session had ended: the connection was lost while it ran)`.
- Red first (4437c3cf): tests/test_acts.py `I14` (two cases), `Exits` (4), `Clients` (2); 7 red before the fix, 219 tests ok after.
