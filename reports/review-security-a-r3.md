1. MAJOR crates/chora/src/input.rs:741-788 (grab_button) -> InputButton/InputMoved (crates/chora-scene/src/event.rs:111-145, no `injected` field). An injected modifier plus a click reaches a window manager's button grab as `input.button`, and the event looks like a person's. I proved this with a scratch core test in a temp copy: the agent injects [{key:125 pressed},{click},{key:125 released}], and the wm with the grab `Super+BTN_LEFT` gets `input.button` pressed and released with no flag. Effects with the switch off:
   - construct (input.rs:295-308, camera.rs:473, `{modifier}+BTN_LEFT`): press() FocusNode LOOK and moves the pane under the pointer; drag_from_window -> leave_window flies out of the window.
   - xp (wm.rs:1825): grab_cube turns the cube.
   - tiling (main.rs:683): drags a window between tiles.
   - mc (main.rs:863): drag.
   hears/from_person cannot see this, and the optout gate only covers events that already have `injected`. So the class is still open through this path.
   Fix: add `injected` to InputButton (and InputMoved, from the grab's press) in the core, using `ButtonGrab.real`/`real_press_of` which already exist. List them in from_person and in the kit test that checks from_person names every event with the field. Drop or refuse them in each WM.
   Earliest gate: a core unit test like the one above (input.rs tests). Then the kit test from_person_knows_every_event_with_an_injected_flag picks it up automatically.
2. MAJOR plugins/chora-tiling/src/main.rs:695-699 + wm.rs:377. PointerEntered has no `injected` field, and tiling's default is `focus: follow_mouse` (tiling.yaml:72). With the switch off, an injected pointer_move over a window gives that window the focus, and injected keys then type into it ("no focus, no keyboard to a window"). The report calls this an "open design point". tests/gate-injected-presses.sh:147 sets `focus: click`, which hides it. docs/configuration.md:189-211 does not list it.
   Fix: carry `injected` on PointerEntered (the core knows `state.injecting`). pointer_focus must then ignore an injected entry unless the switch accepts it.
   Earliest gate: a tiling unit test of pointer_focus with an injected entry, then the e2e tiling cell run with follow_mouse.

5. MINOR tests/injected-optout.py:61-62. `injected: _x` (any underscore-prefixed binding) counts as "named". Rust gives no unused warning for it, so it drops the flag silently. Fix: accept only the shorthand `injected` or `injected: true|false`, and refuse `injected: _\w*`. Add these as guards.sh cases. Earliest gate: guards.sh.
