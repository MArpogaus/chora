### 2. Severity
MAJOR holds: a key reaches the hidden window (2 of 12 runs; with an xp click that gives xp no node focus, forever).

### 3. Cause
`open_cube` (plugins/chora-construct/src/cube/construct.rs) leaves `core_focus` on the window that had the keyboard; the cube covers the pane (`in_sight` false, `state.rs:32` `shown: self.active && in_sight(pane)`), but nothing releases the keyboard. `focus_value` (state.rs:67-68) says holder construct for an owned `core_focus`. The one guard that releases an unseen focus, `unseen_focus_to_walk` (camera.rs:331), returns at once with `self.cube.is_some()`:
```
if self.in_pane() || self.cube.is_some() || !self.active || self.overlay { return Ok(()); }
```
The core keeps s1 as the key target until another client takes a focus. Usually the face click does (xp `focus.node`, the core clears the surface focus: `leave` in the probe log); in about 1 of 6 runs it gives xp no node focus at all and s1 keeps the keys. Why that click gives xp no focus (a click before the face takes it) is not found here: the icons (xp-icons, children xp-icon-0..2) exist at click time in the bad runs too, so it is not a missing icon; it is a core or xp face-click question, left open, no longer a key hazard after the fix.
