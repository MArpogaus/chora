## Findings

1. MAJOR plugins/chora-assistant/src/chat/host.rs:373-379 (chat_pressed), tests/gate-hud.sh:108,420-421. No test proves that a person's click (injected=false) on the "Chat ..." row still opens the chat. The unit tests cover only the predicate `refuses_injected` (view.rs:1655) and `toggles_chat` for the figure; `chat_pressed(ROW, false)` / `chat_row()` is never called from a test. The gate cell chat-row-click-opens became chat-row-injected-click-refused (negative only), and the other cells open the chat by chat.show; the tests/doors/*.sh scripts that run with --test-injected-press-is-real click hud-chat-close, the helper word and hud-figure, but none clicks hud-row-chat. The code reads correct, but a regression (e.g. `refuses_injected` made unconditional, or the real-press path of the row broken) would pass every unit test and gate, and the row is the main way to open the chat (RC criterion 1). Fix: a unit test that drives chat_pressed(ROW, false) vs (ROW, true) with a fake core, or a hud-gate cell that runs with --test-injected-press-is-real (second session) and clicks hud-row-chat. Earliest gate: assistant unit test.
2. MINOR tests/injected-optout.py:92-103 (opt_outs). The brief says accept only `injected` or `injected: true|false`; the script accepts any other binding that is not `_name`. Scratch probe (file in the scratchpad, rc=1 only for the lines listed as refused): accepted without comment: `injected: inj` (rustc's unused_variables, caught by -D warnings, so only when the name is used), `injected: ref _x`, `injected: x @ _`, `injected: (_)`, `injected: _ | true`. Refused correctly: `injected: _`, `_x`, `r#injected: _`, any `..` without the field named, `Self::`/`E::`/`use Event::*` variants and a variant name split over lines. Fix: accept the target only if it is `true`, `false`, or the shorthand, or (if names are wanted) require the name to be used. Add guards.sh cases. Earliest gate: guards.sh.
3. MINOR plugins/chora-mc/src/main.rs:815, plugins/chora-assistant/src/main.rs:245. mc and assistant `event` have no driven wiring test. Deleting the single `hears_pointer` call keeps every unit test green (the arms of mc InputButton/PointerScroll/PointerEntered and assistant PointerEntered carry only a `// injected: Plugin::event drops ...` comment, which the optout check accepts as a reason without verifying it). Severity: MINOR, not MAJOR, because the guard is one line at the top of each function, the predicate is tested (kit test from_person_knows_every_event_with_an_injected_flag covers the flag of from_person, hears_pointer itself only through the other plugins' tests), and the mc/assistant press and key arms check the flag locally. Fix: one test each that sends an injected pointer.scroll / pointer.entered (and input.button for mc) and asserts no state change.

A new flagged event added to from_person but not to hears_pointer would reach mc/construct/notify/assistant. Fix: derive one from the other or test both.
