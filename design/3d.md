# Robust 3D in chora

Draft of 2026-11-09 on commit 0d1a24b, revised after review round 1. It
replaces the spike of D68: the owner builds robust 3D now, without the
hardware measurement. 2D must not suffer. Section 7 holds the draft D75.

## 1. Current state

- **Transforms.** `Transform` is a column-major `[f64; 16]` with
  hand-written `then`, `apply` and `scale_2d`, and no inverse or
  decomposition (`crates/chora-scene/src/transform.rs:15`, `:182`, `:210`).
  `scale_2d` accepts a negative scale; `location_and_scale` then drops
  the node (`render.rs:547`). glam 0.33 is in `Cargo.lock` (#83).
- **Layers.** A node with a `size` and a mesh, effects, a clip, a shape, a
  shader, or an own transform that is not 2D is a layer (`node.rs:250`).
  It renders its subtree into a texture in every frame (`render.rs:245`)
  with a fresh damage tracker (`mesh.rs:221`), bumps its commit in every
  frame (`mesh.rs:164`) and draws as a `MeshElement`. Textures are keyed
  by exact size (`mesh.rs:151`). A surface, text, image without size or
  group under a rotation draws nothing (#48).
- **Perspective.** `mesh.rs:331` projects grid points to (x, y, w) and
  `clip_space` writes z = 0 (`mesh.rs:470`), so GL clips at w = 0 and
  nothing tests depth. The CPU still drops each triangle with a point at
  w <= 1e-6 (`mesh.rs:350`). Triangles draw in index order.
- **Cameras.** The output camera is 2D only (`scene.rs:128`). The
  construct builds projection times view times model with a zero z row
  (`plugins/chora-construct/src/space.rs:190`), sorts panes by centre
  depth and sends per pane, per frame a matrix, haze, edge, mirror and
  glow (`main.rs:2025` to `2160`), plus fog uniforms (`main.rs:1972`).
  `chora-xp` uses w = 1 + z / focal (`plugins/chora-xp/src/cube.rs:233`).
- **Panes.** A pane is a shader node reading its window as node texture
  `win` (`main.rs:588`); its mirror reads the same window again
  (`main.rs:623`), and node textures are keyed by consumer
  (`render.rs:298`), so the window renders twice. The window sits at
  opacity 0 under `construct-windows`.
- **Hit test.** `hit` (`render.rs:678`) inverts 2D transforms only; a
  tilted layer takes input over its box and gives it to nobody
  (`render.rs:723`). The construct casts its own ray (`space.rs:410`).
  During a press, Smithay's click grab keeps the surface and updates its
  location only while the hit stays on it (`input/pointer/grab.rs:367`).
- **Popups.** `popup_area` (`handlers.rs:472`) uses the window translation
  only. Smithay draws and hits popups with the `Window`, relative to the
  geometry origin, which is also the texture origin (`render.rs:419`).
- **Other.** `animate` blends matrix entries (`animation.rs:179`, #78).
  Effects lack the scale (#79). Projected edges alias (#76). No direct
  scanout. `output.add` is headless only (`backend/headless.rs:47`).

## 2. Strategy

### 2.1 From option B

The hit test through flat 3D transforms comes in this plan: the inverse
of the plane homography, then the 2D hit test inside the plane. The other
three blocks of D68, the portal `forward` (D70), an output as a texture
source and virtual outputs (D69), follow in a later plan for K6 and K7;
nothing here blocks them.

### 2.2 Planes

A **plane** is a visible node with a size whose transform, relative to
its nearest layer, is not a 2D translation with a positive scale. The
size is `size`, or the content: the window geometry of a surface, the
file of an image (`render.rs:738`), the layout of a text (`text.rs`). The
core computes this size; `Node::is_layer` stays in the scene crate. A
group without a size passes its transform on, so each child below it
becomes its own plane. Nothing is refused, so a rotated window, a
mirrored node and a node without size render (0.10 gate 3, #48).

Outside a 3D context, planes draw in scene order, as today.

### 2.3 From option A, and why

One part of option A is needed: a 3D context. A group with a `size` and
`perspective: d` puts its descendants in one 3D space, with the eye at
distance d in front of its centre, looking along +z (x right, y down).
A point projects with w = 1 + z / d, as in `chora-xp`; z = 0 shows at
1:1. The camera is the transform of a child group without size. The core
needs the eye for:

- **Order.** A centre depth sort fails for planes that cross and for a
  large far plane behind a small near one. The core sorts and splits the
  planes of a context with the crate `plane-split` 0.18 (WebRender's
  BSP; MPL-2.0, allowed by `deny.toml`; its `euclid` is already in the
  tree). Coplanar planes keep scene order, so a glow stays behind its
  pane. A mesh with `depth` sorts as one unit; optionally its triangles
  sort back to front.
- **Near clip.** GL already clips at w = 0. The CPU stops dropping
  triangles and computes bounds from the polygon clipped at w = 1e-6; in
  a context, `plane-split` clips at w = 1/64 before the sort.
- **Ray hit test.** The ray from the eye takes the nearest plane that
  accepts input, maps the hit to (u, v) and runs the 2D hit test of the
  plane. Input reaches the window, its subsurfaces and its popups. Hit
  order equals draw order.
- **Camera cost.** A shader in a context gets `uniform float depth` (eye
  distance of the plane centre over d, 1 at 1:1) and `uniform float
  facing` (cosine of the view angle). Haze, edge width, fresnel and glow
  then follow the camera without updates; a walk sends the camera
  transform and the fog uniforms, 2 updates instead of about 3 per pane.

A plane that projects to a plain 2D transform (z = 0, facing) draws on
the 2D path: a pane flown in at 1:1 is pixel exact.

### 2.4 Cost of a plane

- A leaf plane (rect, unsliced image, text, surface with one buffer and
  no subsurface or popup, no effects) draws its own texture through the
  projected quad: no offscreen pass.
- Other planes keep a damage tracker each and render only when a surface
  commits or a node of the subtree changes; the `MeshElement` commit
  bumps only then or when the shape moves.
- Node textures render once per frame per source and size, so a mirror
  reuses the texture of its window.
- The texture scale follows the projected size in power of two steps of
  the output scale, so a walk does not allocate (0.10 gate 4).
- Planes that are not 2D get mipmaps when minified and an edge feather
  from the uv distance to the texture border (#76). Split and clip edges
  lie inside the uv square and get no feather.

### 2.5 Boundary and what stays out

The core draws worlds of planes: panes, labels, charts, images and shader
nodes that ray march. Dense geometry (point clouds, molecules, terrain)
belongs in a Wayland client with its own depth buffer, shown as a plane
with ray input. Out: a depth buffer (translucent edges and coplanar
layers need a sort anyway; Smithay's framebuffers have no depth
attachment), a new renderer, a node kind, a 3D output camera (D40),
lights and models.

### 2.6 API changes

| Change | Kind |
|---|---|
| `perspective` (1 to 10^6 logical pixels) on a group with `size` and a 2D own transform | new property |
| any node takes any transform; nodes without size use their content size or pass it on | rule |
| `local: [u, v]` in `pointer.pressed`, `pointer.moved`, `pointer.released` | new event field |
| `uniform float scale` for effects and shader nodes; `depth` and `facing` in a context | new uniforms |
| `animate` interpolates translation, rotation (slerp) and scale apart; a matrix that does not decompose blends as today | behavior |

No new method, no new node kind.

## 3. 2D protection

A scene without 3D content has no `perspective` and no plane. For it:

- `Scene::walk` gains one branch at `perspective`; otherwise the walk and
  its lists are unchanged. The 2D shortcut requires a positive scale.
- `elements` (`render.rs:209`) leaves 2D layers (rounded rects, effects,
  clips) on their path; per plane damage, texture steps, mipmaps and the
  feather apply only to planes (`feather = 0` otherwise).
- The hit test walks `hit_list`, which stops only at planes and contexts;
  for a 2D scene it equals `draw_list`, so `hit` does the same math.
- `Transform::then` and `apply` keep their code; glam serves the inverse
  and decomposition. A translation and scale animation keeps the entry
  blend, bit for bit.

Tests of step 0, before any change:

- `RenderStats` in `Assets` counts offscreen passes (`render_into`,
  `draw_pass`), texture allocations, frames with damage, planes, splits.
- `a_2d_scene_takes_no_3d_path`: a rect, a text, an image, a probe
  window, a layer surface and a zoomed camera. It asserts the variant
  sequence of `output_elements` (no `Mesh`), 0 offscreen passes, 0
  planes, and `GL_NONE` for the depth attachment of the output target.
- `a_static_2d_scene_renders_once`: the same scene has damage in frame 1
  only, over 60 frames.
- `hits_match_the_flat_walk`: 200 random 2D scenes (translate, positive
  scale, clips, input modes, rounded rects); `surface_under` and
  `node_under` equal a copy of today's flat draw list search, kept in
  the test as the reference.
- One rounded rect: 2 offscreen passes per frame, as on the base.
- `tests/2d-guard.sh` compares base and HEAD captures after every step.

## 5. What it enables for construct

- **K5 Direct input.** The space becomes a group with
  `perspective = lens.focal`, the pose one child group. An own window
  becomes its own pane: a sized group with the surface and the effect
  `pane.frag`, which reads `depth` and `facing` for haze and edge. Clicks
  reach the window through the ray; navigate mode keeps its grab.
- **K6, K7.** A desktop pane and WM panes need the later plan (portal,
  output texture, virtual outputs); the ray hit, popups and plane damage
  of this plan carry them.
- **K8 Drop to give.** `local` and the ray name the pane and the point
  under a drag, also outside the dragged plane.
- **K9 Cylinder and wall.** A ring of planes in one context, ordered from
  inside; a scroll is one `animate` of a rotation, which turns (#78).
- The construct drops its depth sort, its ray and most per pane updates.

## 6. Risks and open questions

Each item ends with the recommended default.

1. **Unmeasured cost.** Tests prove function, not 60 fps. Default: print
   frame times, hand `tests/3d-bench.sh` to the user in `HANDOFF.md`.
2. **Depth buffer later?** Meshes that cross need one. Default: none; a
   client draws dense geometry (2.5).
3. **Plane count.** Data worlds have many planes; software GL spends 60
   to 140 µs per draw. Default: sort and split up to 1,024 planes per
   context, beyond that a centroid sort, with a log line; the frame
   watchdog (D23, D64) handles the rest.
4. **Popup area.** A menu larger than its window slides or shrinks.
   Default: the window geometry, which is the texture.
5. **Back faces.** Default: a plane seen from behind draws mirrored and
   takes input; the plugin hides back faces (D19).
6. **Pointer constraints.** Default: a lock works; a confine region does
   not activate on a surface in a plane.
7. **Panorama (D66).** Default: one context in scene coordinates spans
   the outputs; each 2D output camera shows its part.
8. **2D layer damage.** Rounded rects still render every frame. Default:
   per plane damage first; 2D layers get it later with their own move of
   `base_2d`.
9. **Direct scanout.** None exists; a context never wraps a fullscreen 2D
   surface. Default: the user measures latency with the bench script.
10. **Review round 1, kept as written.** The depth attachment check stays
    in the test of section 3: the charter names it, it costs one GL
    query, and it fails if a later change adds a depth buffer. An edge
    mask per vertex is not needed: the feather uses the uv distance to
    the texture border, so split edges get none by construction.
