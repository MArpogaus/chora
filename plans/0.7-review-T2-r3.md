# Review of T2, round 3

Note: the given range `6c0b33f..HEAD` is empty because HEAD *is* `6c0b33f`.
This review therefore covers the T2 work `5d20791..HEAD` (a1038d9, ed937d8,
6c0b33f), i.e. 6c0b33f on top of what round 2 saw. fmt, clippy and the ipc
tests pass at HEAD. Findings 3 to 5 are the round 2 findings that 6c0b33f

- crates/chora/src/ipc.rs:996 - a surface the renderer never draws still gets a rect, and a mirrored one gets a negative box. A surface node can never be a layer: `check_kinds` rejects `size` for surfaces (crates/chora-scene/src/scene.rs:1248) and `is_layer` needs a size (crates/chora-scene/src/node.rs:247). A rotated, mirrored, collapsed or perspective-transformed surface is therefore dropped by the renderer (`location_and_scale` at crates/chora/src/render.rs:402 returns no elements), while `window_rect` (crates/chora/src/render.rs:815) answers the affine box anyway; under `scale_2d().unwrap_or((1.0, 1.0))` a rotation reports a full box for pixels that exist nowhere, and a mirrored surface at x 400 with w 200 yields `[400, y, -200, h]`, which passes `overlaps` and lands in the JSON. The renderer already states the rule in its test `mirrored_and_collapsed_nodes_are_not_drawn` (crates/chora/src/render.rs:862) and `hit` applies exactly it (crates/chora/src/render.rs:667, then `layer_hit` at 703 takes the `mesh::shape` box); `screen_rect` copies neither. Non-layer rect and image nodes with a negative or zero scale get rects for the same reason, and a zero scale yields a zero-area rect that `overlaps` still passes, e.g. `[50, 50, 0, 0]`. Fix as in `hit`: for a non-layer node require `location_and_scale(transform)`, for a layer node take the `mesh::shape` box; add tests for a mirrored surface and a rotated image without size.
- crates/chora/src/ipc.rs:1012 - a shader node is left out on every output, but a shader with a size is always a layer (crates/chora-scene/src/node.rs:247) and the renderer draws it through `layer` wherever it stands, also on its own outside any layer (crates/chora/src/render.rs:212, called with `layer_list(ROOT)` at 162), and `hit` answers `Hit::Area` for it (crates/chora/src/render.rs:686). The comment "a shader only draws inside a layer" is wrong, and the node draws yet never gets a `rects` entry, against the `rects` row of docs/api.md:47 which names all nodes. Take the box like a rect when the node has a size, leave it out without one; add a query test for a visible shader node.
- crates/chora/src/ipc.rs:958 - `screen_rects` walks `draw_list()` and `overlay_draw_list()`, which descend into layer nodes (crates/chora-scene/src/scene.rs:793), while the per-output frame composes `layer_list` and `overlay_layer_list` (crates/chora/src/render.rs:160, 162), which stop there and show the layer as one texture warped by its own mesh. Two results: a node whose box lies fully outside the size of an ancestor layer (a group with a mesh, effects or a rotation, but no explicit `clip`, so `placed.clips` has no entry, crates/chora-scene/src/scene.rs:778) is drawn nowhere yet keeps a rect, breaking "Leave out outputs where the node is not visible"; and a node inside a layer with a deformed mesh keeps its un-warped box, which is not the bounding box the docs row promises. Add the box of each ancestor layer to the intersect loop as a clip does, and either project through the mesh of an ancestor layer or say in docs/api.md:47 that the mesh of a layer does not move the boxes of its descendants; test a node fully outside a meshed group.
- crates/chora/src/ipc.rs:1017 - open from round 2: the clip box still comes from `bounding_box`, whose `Transform::apply` (crates/chora-scene/src/transform.rs:195) ignores the w row, so a clip under a matrix that divides by w is cut to the affine box instead of the projected quad the renderer draws (the clip node is a layer and shows through `mesh::shape`); descendants that draw are cut away or kept that do not. Round 2 asked to take the clip box through `mesh::shape` or to note the affine limit in the comment at 1014; 6c0b33f did neither.
- docs/api.md:47 - open from round 2: the `rects` cell is still one sentence of about 65 words with the passive "are left out", against the plan rule of at most 25 words per sentence and active voice; 6c0b33f only appended "inside a clip, cut to the clip area" to it. Split at the semicolons into short active sentences as round 1 sketched, and keep the new text true against the findings above.
