# Work plan 0.7 for a local pi agent

This plan is for an unattended pi session on a small model. Do the tasks
in order. Do not invent extra tasks. The scope and the gate of 0.7 are in
`docs/roadmap.md`; the gate issue is #91.

## Rules (read first, follow always)

- Repo: `~/Projekte/chora`, branch `dev`. Never push. Never rewrite
  history (no amend, no rebase, no reset). Never touch `services/voice/`.
- Cargo is not on PATH: run `micromamba run -n chora cargo ...`.
- Before each commit run, and fix until all pass:
  1. `micromamba run -n chora cargo fmt --all`
  2. `micromamba run -n chora cargo clippy --workspace --all-targets --locked -- -D warnings`
  3. `micromamba run -n chora cargo test --workspace --locked`
- Tests that render need the Mesa EGL variables of CONTRIBUTING.md. Tests
  that failed before your change for lack of a GPU may stay red; compare
  with a run on the commit before your change.
- Commits: conventional, imperative, at most 68 characters in the subject,
  for example `feat(ipc): mark the focused surface in queries`. Stage files
  by name. No AI attribution lines.
- One task = code + a test that fails without the change + the docs line
  in `docs/api.md` or `docs/configuration.md`. Docs: at most 25 words per
  sentence, active voice, no em or en dashes.
- If a task needs more than about 300 changed lines, or you are not sure
  what the right behaviour is: stop that task, write `status: open (ask
  Marcel)` with your question in `plans/0.7-state.md`, and go to the next
  task.

## Session mechanics

Follow `~/.agents/skills/local-pi-session/SKILL.md` and its
`reference.md`:

- One driver script loops over the tasks below, one at a time.
- A heartbeat restarts the driver if it dies. There is no cron in the
  sandbox, so use a `setsid` sleep loop.
- At most 2 pi sub-agents at the same time, each with a session (not
  `--no-session`), each under `timeout 3600`.
- State lives in `plans/0.7-state.md`, one line per task:
  `T<n>: todo | doing | review | done <sha> | open (<reason>)`.
- For each task:
  1. An implement sub-agent does the task and commits.
  2. A review sub-agent reads `git show <sha>` read-only and writes
     findings, or a line that is exactly `CLEAN`.
  3. An audit of its transcript checks that it read the diff and changed
     nothing.
  4. If there are findings, the implement sub-agent fixes them with new
     commits, then review again.
  5. After 3 rounds without `CLEAN`, mark the task `open`.
- When all tasks are `done` or `open`, write `plans/0.7-done.md`: one line
  per task with its commits, then stop the heartbeat.

## Tasks

### T1: focus in queries

- Goal: `scene.query` marks the surface with the keyboard focus and the
  node with the node focus, with `"focused": true`. Nodes without focus
  leave the field out.
- Look at: `crates/chora/src/ipc.rs` (`fn query`, about line 915),
  `crates/chora-scene/src/scene.rs` (`focused_node`, the focused surface).
- Test: in the tests of `ipc.rs`, focus a surface and query it; then focus
  a node with `focus_node` and query it.
- Docs: a `focused` row in the node table of `docs/api.md`.
- A client socket still sees only its own nodes (rule 5 of A1). Its query
  shows `focused` only on its own nodes.

### T2: screen rectangle in queries

- Goal: each node in a query gets `rects`: a map from output name to
  `[x, y, w, h]` in logical output pixels, after all parent transforms
  and the camera of that output. Leave out outputs where the node is not
  visible.
- Look at how the renderer composes transforms and cameras. Reuse that
  code, do not write a second copy.
- Test: a rect under root with a translate and a scale, a camera with a
  pan, and the expected rectangle.
- Docs: `rects` in the node table.
- If rotation or a mesh makes the shape no rectangle, give the bounding
  box and say so in the docs.

### T3: `choractl wait SELECTOR`

- Goal: `choractl wait SELECTOR [--timeout SECS]` polls `scene.query`
  every 100 ms, prints the matching nodes as one JSON line and exits 0.
  After the timeout (default 10 s) it exits 1 with a message on stderr.
  With `--gone`, it waits until nothing matches.
- Look at: `crates/choractl/src/main.rs`, the `query` subcommand.
- Test: a unit test of the poll loop with a fake query function, or a
  test in the style of the existing choractl tests.
- Docs: the choractl section of `docs/configuration.md` or `docs/api.md`,
  wherever `query` is described.

### T4: `hold` for injected buttons

- Goal: an injected button event with `"hold": true` stays down after the
  request ends. A later event releases it. Without `hold`, the core
  releases buttons at the end of the request as today.
- Look at: `crates/chora/src/input.rs` (the inject code and its auto
  release).
- Test: press with `hold`, end the request, check that the button is
  still down; release in a second request.
- Docs: the inject section of `docs/api.md`.

### T5: dry run for `input.inject`

- Goal: `input.inject` with `"dry_run": true` checks every event (names,
  key symbols, limits) and answers ok or the error, without sending
  input. `choractl inject --dry-run` sets it.
- Test: a batch with a wrong key symbol fails in a dry run; a good batch
  passes and sends nothing.
- Docs: the inject section of `docs/api.md`.

### T6: compact JSON from `choractl spawn`

- Goal: `choractl spawn` prints its answer as one line, like other
  commands that scripts read. Check how `query` prints and do the same.
- Test: the output has no newline inside the JSON.

### T7: a clear error for a taken client name

- Goal: `choractl clients create NAME` for a name that already has a
  socket prints `NAME has a client socket already: PATH` on stderr and
  exits 1.
- Look at: `crates/choractl/src/main.rs` (`clients`), and the error data
  that `clients.create` returns.
- Test: create twice; the second fails with the message.

### T8: `chora-probe window --exit-on-close`

- Goal: with `--exit-on-close`, the probe window ends its process when it
  gets `xdg_toplevel.close`. Without it, nothing changes.
- Look at: `tests/probe/src/main.rs` (the `chora-probe` crate), and
  do it the same way as `--server-deco`.
- Test: if the probe has tests, add one; else check it by hand in a
  headless session and write the commands into the commit message.

### T9: `tests/ipc-bench.sh` on the headless session

- Goal: `ipc-bench.sh` starts `tests/headless-session.sh` instead of a
  headless sway, and reads `CHORA_SOCKET` from its output. Keep the
  measurements the same.
- Check: run it once and paste the result lines into the commit message.

### T10: methods of chora-tiling

- Goal: `chora-tiling` exports methods with `methods.export`, next to
  `set_layout`, `get_layout` and `give`:
  - `view_tag(tag)`;
  - `move_to_tag(surface, tag)`;
  - `focus(surface)`;
  - `focus_next()` and `focus_prev()`;
  - `swap_master(surface)`.

  Each one does what its key binding does.
- Look at: `plugins/chora-tiling/src/main.rs`, how `give` is exported and
  how the bindings act.
- Test: unit tests in the model of `chora-tiling` (`wm.rs`), one per
  method.
- Docs: the `chora-tiling` section of `docs/configuration.md`, a table of
  the methods.

### T11: methods of chora-xp

- Goal: `chora-xp` exports these methods:
  - `start_menu(open)`;
  - `minimize(surface)` and `restore(surface)`;
  - `activate(surface)`;
  - `restart()`;
  - `turn_to(desktop)`.

  Each one does what the click does.
- Look at: `plugins/chora-xp/src/wm.rs` (`taskbar::Part::Task`,
  `minimize`, `activate`, `turn_to`, the Restart path in
  `wm/restart.rs`), and how chora-tiling exports methods.
- Test: unit tests where the window manager can run without a core;
  otherwise a step in `tests/xp.sh`.
- Docs: "The XP flavor" in `docs/configuration.md`, a table of the methods.

### T12: check the first click on the active task button

- The battle test saw that the first click on the task button of the
  active window did nothing, and the second minimized it. The code
  (`wm.rs`, `taskbar::Part::Task`) minimizes when `is_active` is true.
- Goal: find out if `is_active` is false after the focus came by
  injected input or by `focus.changed`. If it is a bug, fix it with a
  test. If XP is right and the harness was wrong, write that into
  `tests/battle/FRICTION.md` and change nothing else.

### T13: battle workflows on the new primitives (gate check 10)

- Goal: `tests/battle/w1.sh` to `w8.sh` use `choractl wait`, `focused`,
  `rects` and the plugin methods of T10 and T11 instead of pixel clicks
  and sleeps. Delete helpers that are then unused (`geom.py`,
  `positions.py`, `pick.py`) if nothing else uses them.
- Check: run each workflow once in a headless session and paste the
  result lines into the commit message.
